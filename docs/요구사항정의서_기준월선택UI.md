## 0. 화면별 월구분 검토 (확정 후보)

운영 원칙: **모든 실적·재고·정산은 달력월(1일~말일) 단위**.  
앱 전역 `state.selectedMonth` 하나. 월이 필요한 화면은 그달 자료만 보여 준다.

### 0.1 화면 분류표

| 화면 / 작업 | 월 선택 UI | 자료 범위 | 월 키(기존) | 권장 |
|-------------|:----------:|-----------|-------------|------|
| 실물 검수 | **필요** | 선택월 입고만 | 거래일 C → `yyyy-MM` | ✅ 월 셀렉트 |
| 재고 및 발주 | **필요** | 선택월 재고행만 | A 기준월 | ✅ 월 셀렉트 |
| 거래처 금액 검증 | **필요** | 선택월 거래일만 | 거래일자 B | ✅ 월 셀렉트 (목록 필터) |
| POS 판매내역 | **필요(연동)** | 선택월 1일~말일 | 판매일자 | ✅ 월 바뀌면 시작·종료 자동. 일별 미세조정은 date 유지 |
| 단가 추이 | **선택(혼합)** | 기본=선택월 / 비교=1·3·6·12개월 | 입고 거래일 | △ 헤더에 선택월 표시. **추이 버튼은 비교용으로 유지** |
| 원재료 코드 관리 | 불필요 | 마스터 전체 | 없음 | ❌ 월 UI 없음 |
| 입고대기 대량OCR | 불필요 | Drive 폴더 | 없음 | ❌ |
| 원재료입고반영 | 표시만 | **선택월** 입고만 환산(권장 변경) | 거래일 | △ 버튼은 코드관리. 실행 시 선택월 사용 |
| 실시간 재고 계산 | 표시만 | **선택월**만 재계산(권장 변경) | A 기준월 | △ 재고 화면 버튼. 선택월 대상 |
| 월마감 진행 | 표시만 | **최신월→다음월** 고정 | A 기준월 | △ 셀렉트 없음. 확인창에 대상월 명시 |
| 거래처관리 / 레시피 | 불필요 | 마스터 | 없음 | ❌ (시트 직접) |

### 0.2 한눈에: 필요 vs 불필요

**월 구분이 필요한 화면 (자료가 달에 묶임)**  
1. 실물 검수  
2. 재고 및 발주  
3. 거래처 금액 검증  
4. POS 판매내역 (월 → 일자 구간)  
5. (느슨히) 단가 추이 — 선택월 기본, 비교 기간 병행  

**월 구분이 필요 없는 화면 (마스터·폴더·일회 배치)**  
1. 원재료 코드 관리  
2. 입고대기 대량OCR  
3. 거래처관리·레시피배합표·원재료관리 시트 자체  

### 0.3 테이블(시트) 추가 사항 검토

| 시트 | 현재 월 판별 | 컬럼 추가 | 결론 |
|------|--------------|-----------|------|
| `원재료_실시간재고` | A **기준월** 이미 있음 | 불필요 | 그대로 |
| `원재료입고` | 거래일(C) → `yyyy-MM` | **불필요** (중복 컬럼 비추천) | 거래일 기준 유지 |
| `거래처매입누적` | 거래일자(B) → `yyyy-MM` | **불필요** | 조회 시 월 필터 |
| `발주내역` | 발주일자 → `yyyy-MM` | **불필요** | 선택월 발주만 표시·저장 권장 |
| `pos판매내역` | 판매일자 | 불필요 | 일자 구간 = 월 1~말일 |
| `일별날씨` | 일자 | 불필요 | POS와 동일 구간 |
| `원재료관리` | 마스터 | 불필요 | — |
| `거래처관리` | 마스터 | 불필요 | — |
| `레시피배합표` | 마스터 | 불필요 | — |

**시트에 새 컬럼을 넣지 않는 이유**  
- 이미 날짜/기준월로 달력월을 계산할 수 있다.  
- `기준월`을 입고·매입누적에 또 넣으면 OCR·검증계산과 **이중 관리·불일치** 위험이 크다.  

**코드/동작만 바꿀 것 (스키마 변경 아님)**  
- 전역 `selectedMonth` + 각 API `month` 인자  
- `jobRebuildVendorBalances`: 시트는 전체 재생성 유지 가능. **화면 `balanceList`만 선택월 필터** (1차)  
- `jobCalculateInventory` / `jobUpdateReceiptQuantities`: 1차에서 **선택월 대상**으로 변경할지 여부 → §7 D11  
- 월 목록: `원재료_실시간재고` A열 ∪ (선택) 입고 거래월 — 기본은 재고 시트 월 목록

### 0.4 구현 1차 범위 (확인용)

| 포함 | 내용 |
|:----:|------|
| ✅ | 전역 기준월 셀렉트 (검수·재고·검증 헤더에 동일 컨트롤) |
| ✅ | `stockList` / `inspectionList` / `balanceList` / `saveInspection` 에 `month` |
| ✅ | POS: 월 변경 시 `posStart=월1일`, `posEnd=월말` 자동 세팅 |
| ✅ | 단가: 헤더에 선택월 표시 + 기본 조회를 선택월 1~말일로 (1·3·6·12는 비교 모드로 유지) |
| ✅ | 과거월 배너, 월마감은 최신월만 |
| ❌ | 시트 새 컬럼 추가 |
| ❌ | PC 패널 동기화 |
| ❌ | 월간 손익 리포트 화면 |

## 1. 배경과 목표

### 1.1 배경

현재 서버는 거의 모든 조회·배치에서 `latestMonth_()`만 사용한다.

| 기능 | 현재 동작 |
|------|-----------|
| `stockList` | `원재료_실시간재고`의 **최대 기준월**만 반환 |
| `inspectionList` / `saveInspection` | 동일 최대 기준월에 속하는 입고만 |
| `balanceList` | **전체 기간** 행 표시 (월 필터 없음) |
| `priceList` | 오늘 기준 최근 N개월 롤링 |
| POS | 기본 최근 약 30일 구간 (월 고정 아님) |
| `jobUpdateReceiptQuantities` | 열린(최신) 달 입고만 환산 |
| `jobCalculateInventory` | 최신 달만 재계산 |
| `jobMonthlyClose` | 최신 달 → 다음 달 이월 |

화면에는 `state.month` / `state.stockMonth`가 **서버가 준 최신월 표시용**으로만 있고, 사용자가 바꿀 수 없다.  
월마감 직후 UI가 바로 다음 달만 보이므로, 지난달 미검수·조정·대조가 어렵다 (`월마감_체크리스트` §1 주의사항).

### 1.2 목표

1. 사용자가 **기준월(`yyyy-MM`)을 선택**하면 **해당 월 1일~말일 자료만** 본다.
2. 기본값은 항상 **최신 기준월**(`latestMonth_`)이다.
3. 월이 필요한 화면은 **같은 선택월**을 공유한다.
4. **조회**와 **위험 배치(월마감 등)** 를 구분해 오조작을 막는다.
5. 기존 UI·`Index.html`·시트 컬럼은 유지하고, 필터·API만 추가한다.
6. API `month`는 선택적. 미전달 시 최신월(하위 호환).

### 1.3 비목표 (이번 범위 밖)

- 월간 P&L / 매입·사용 리포트 전용 화면
- 월마감 전 자동 차단(미검수 있으면 버튼 비활성) — 별도 과제
- 시트에 `기준월` 컬럼 신규 추가
- 카톡 자동 전송
- PC 패널(`inventory_panel.py` / `sheet_jobs.py`) 동기화 (GAS만 SSOT)

## 2. 용어 정의

| 용어 | 정의 |
|------|------|
| 기준월 | `yyyy-MM` 문자열. 예: `2026-11` |
| 최신월 / 열린달 | `원재료_실시간재고` A열 중 `textMonth_` 결과가 **사전순 최대**인 달 (`latestMonth_`) |
| 선택월 | 사용자가 UI에서 고른 기준월. 세션 동안 유지 |
| 과거월 | 선택월 &lt; 최신월 |
| 재고행 | `원재료_실시간재고`에서 `기준월 === 선택월` 인 행 |
| 입고 소속월 | `receiptMonth_`: 거래일(C) 우선, 없으면 검수일시(R)의 `yyyy-MM` |
| 검수 포함 규칙 | 기존 `belongsToOpenMonth_(row, disp, month)` — 선택월을 `month`에 넣어 재사용 |

## 3. 현재 데이터 계약 (변경 없음)

### 3.1 `원재료_실시간재고`

| 열 | 헤더 | 역할 |
|----|------|------|
| A | 기준월 | 월 키 (`yyyy-MM` 또는 Date → `textMonth_`) |
| E~I | 이월·입고·사용·조정입고·조정로스 | 해당 기준월 스냅샷 |
| J | 안전재고 | 현재고 앞 (`INV_COL.SAFETY`) |
| K | 현재고 | `INV_COL.STOCK` |
| L | 부족수량 | 현재고 다음 (`INV_COL.SHORTAGE`) |
| M~P | 단위·직관·규격·구분 | `웹앱.gs` INV_COL 주석 유지 |

같은 코드가 **월별로 여러 행** 존재할 수 있다. 월마감은 최신월 행을 남기고 다음월 행을 추가한다.

### 3.2 `원재료입고`

- 월 필터 키: `belongsToOpenMonth_` / `receiptMonth_` (기존 로직 유지)
- 상태: 검수대기 / 반영완료 등 (기존)

### 3.3 월 목록 산출

새 헬퍼(가칭):

```
listInventoryMonths_() → string[]  // 오름차순 yyyy-MM, 중복 제거
```

- 출처: `원재료_실시간재고` 전 행의 A열 `textMonth_`
- 빈 목록이면 오늘 기준 `yyyy-MM` 1개
- API 응답에 `months: [...]`, `latestMonth: "..."` 포함

## 4. 기능 요구사항

### 4.1 공통 — 기준월 선택 컨트롤

| ID | 요구 | 상세 |
|----|------|------|
| M-01 | 표시 위치 | **실물 검수**, **재고 및 발주** 각 화면 헤더(제목 옆 또는 바로 아래). 모바일·데스크톱 모두 |
| M-02 | 컨트롤 형태 | `<select>` (월 목록). 라벨: `기준월` |
| M-03 | 옵션 | `listInventoryMonths_()` 결과. 표시 예: `2026-11` (최신월 옵션에 ` (현재)` 접미사 권장) |
| M-04 | 기본값 | 앱 최초 로드·PIN 통과 후 = `latestMonth`. 선택 이력 없으면 최신월 |
| M-05 | 변경 시 | 해당 화면 데이터 **즉시 재조회** (`loadInspection` / `loadStock`) |
| M-06 | 세션 유지 | `sessionStorage` 키 예: `stockOpenMonth`. 메뉴 전환 시 동일 선택월 유지 |
| M-07 | 동기화 | 검수↔재고 화면이 **같은 선택월**을 공유한다 (전역 `state.selectedMonth`) |
| M-08 | 최신월 갱신 | 월마감·재고계산 성공 후 `months`/`latestMonth` 재수신. 선택월이 목록에 없으면 최신월로 리셋 |
| M-09 | 제목 문구 | 기존 `"{month} 실물 검수"` / `"{month} 재고 · 발주"` 는 **선택월**을 표시 |

### 4.2 실물 검수

| ID | 요구 | 상세 |
|----|------|------|
| I-01 | 조회 | `inspectionList(pin, month?)` — `month` 없으면 최신월 |
| I-02 | 필터 | 기존 날짜/거래처/미검수 필터는 **선택월 결과 집합 위**에서 동작 |
| I-03 | 저장 | `saveInspection(pin, changes, month?)` — 서버는 각 행이 **요청 month 소속**인지 재검증 후 저장 |
| I-04 | 과거월 편집 | **허용(1차)**. 월마감 후에도 지난달 미검수 반영이 필요하기 때문 |
| I-05 | 배지 | 사이드바 검수 대기 배지는 **선택월** 기준 건수 (또는 최신월만 — §7 결정: **선택월**) |

### 4.3 재고 및 발주

| ID | 요구 | 상세 |
|----|------|------|
| S-01 | 조회 | `stockList(pin, month?)` — 선택월 행만 |
| S-02 | 안전재고·조정 저장 | `saveStock`은 **행번호+코드**로 저장(기존). 과거월 행도 수정 **허용**하되, UI에 `과거월 편집 중` 안내 배너 표시 |
| S-03 | 발주 저장 | `jobSaveOrderList`는 실무상 **최신월(운영월)** 기준. 선택월이 과거이면 발주 버튼 **비활성** + 툴팁: `현재 기준월에서만 발주할 수 있습니다` |
| S-04 | 실시간 재고 계산 | 버튼은 **최신월에서만 활성**. 과거월 선택 시 비활성 + 안내 |
| S-05 | 부족/추천 Box | 선택월 데이터로 계산·표시 (과거월은 참고용) |

### 4.4 배치·위험 작업 (월 선택과 연동 규칙)

| 작업 | 1차 동작 | 비고 |
|------|----------|------|
| 입고대기 대량OCR | 월 무관 (드라이브 폴더) | 변경 없음 |
| 원재료입고반영 (`jobUpdateReceiptQuantities`) | **최신월만** 처리(현행). 버튼은 원재료 코드 관리에 있음 → 1차에서 month 인자 추가 **안 함** |
| 실시간 재고 계산 | **최신월만** (현행). 재고 화면에서 과거월이면 비활성 |
| 월마감 진행 | **최신월만** (현행). 선택월과 무관. 확인 문구에 최신월·다음월 명시 강화 권장 |
| 원재료 코드 관리 | 월 무관 | 변경 없음 |

2차(선택): `jobUpdateReceiptQuantities(pin, month)`, `jobCalculateInventory(pin, month)` 로 특정월 재처리 — 본 문서 비목표. 필요 시 별도 지시서.

```json
  "month": "2026-11",
  "latestMonth": "2026-12",
  "months": ["2026-09", "2026-10", "2026-11", "2026-12"],
  "isLatest": false,
  "rows": [ ... ],
  "version": "..."
}
```

| 필드 | 의미 |
|------|------|
| `month` | 실제 조회에 사용된 달 |
| `latestMonth` | 시트의 최신 기준월 |
| `months` | 선택 가능한 달 목록 |
| `isLatest` | `month === latestMonth` |

요청 `month`가 목록에 없으면: **에러** `"기준월을 찾을 수 없습니다: …"` (조용히 최신월로 바꾸지 않음 — 사용자 혼란 방지).  
단, `month` 생략/`""` 이면 최신월.

#### 4.5.2 시그니처 변경(가칭)

| 함수 | 변경 |
|------|------|
| `stockList(pin, month)` | `month` optional |
| `inspectionList(pin, month)` | `month` optional |
| `saveInspection(pin, changes, month)` | `month` optional, 소속 검증에 사용 |
| `Api.gs` 라우팅 | 클라이언트 `month` 파라미터 전달 |
| `listInventoryMonths_()` | 신규 private 헬퍼 |
| `resolveMonth_(requested, values)` | 신규: 빈값→latest, 유효성 검사 |

프론트 `api(action, payload)` 에 `month: state.selectedMonth` 포함.

## 6. 시나리오

### A. 월마감 직후 지난달 확인

1. 최신월이 `2026-12`로 바뀜 (기본 선택 = 12월)
2. 기준월에서 `2026-11` 선택
3. 검수·재고가 11월 데이터로 갱신
4. 발주·재고계산 버튼 비활성 + 배너 표시

### B. 지난달 미검수 마무리

1. 기준월 `2026-11` 선택
2. 미검수 체크 → 저장 → `반영완료`
3. (2차 과제) 11월 재고 재계산이 필요하면 별도 기능; **1차는 저장만 보장**
4. 운영자가 최신월로 돌아가 일상 업무

### C. 잘못된 month 요청

1. API에 `month=2025-01` (시트에 없음)
2. 서버 에러 → 토스트로 메시지 → 선택월을 `latestMonth`로 리셋 후 재조회

### D. 세션 유지

1. 검수에서 `2026-10` 선택
2. 재고 메뉴로 이동 → 여전히 `2026-10`
3. 브라우저 탭 종료 후 재접속 → 최신월로 초기화 (`sessionStorage` 기준)

## 8. 가능 여부 · 장단점 · 추천

| | 내용 |
|--|------|
| 가능 여부 | **가능.** 시트에 월별 행이 이미 있고, 필터만 `latestMonth_` → `resolveMonth_`로 바꾸면 됨 |
| 장점 | 월마감 후에도 지난달 대조·미검수 처리 가능. 체크리스트와 운영이 맞음 |
| 단점 | 과거월 검수 저장 후 **과거월 재고 재계산이 1차에 없으면** 숫자 불일치 가능 |
| 추천 | 1차는 **조회 + 검수/조정 저장 + 위험버튼 가드**. 2차로 `jobCalculateInventory(pin, month)` |
| 대안(비추천) | 월 선택 없이 시트만 보기 → 폰 운영에 불편 |
