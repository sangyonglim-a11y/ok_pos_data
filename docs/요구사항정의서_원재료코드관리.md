## 1. 배경과 목표

### 1.1 배경
- OCR·입고 과정에서 영수증 품목명이 공식 원재료명과 다르게 들어온다.
- 과거에는 별칭을 대표 행의 `영수증별칭`(G열)에 `|`로 이어 붙이거나, 화면에서 품목명을 동적으로 합성했다.
- 현재는 **Dictionary Row(독립 행 기반 별칭)** 구조를 채택한다.  
  - 시트에는 `대표` 행과 `별칭` 행이 **별도 Row**로 존재할 수 있다.  
  - 화면 리스트에는 **1코드 = 1행(대표)** 만 보이며, 별칭은 `aliases[]` 뱃지로만 노출한다.

### 1.2 목표
1. 사장님이 **원재료코드·공식명·규격·환산**을 한 화면에서 조회·수정한다.
2. 미등록(코드 없는) 품목을 **신규 대표 등록** 또는 **기존 코드 연결(link)** 한다.
3. 시트 물리 데이터와 화면 렌더링이 1:1로 대응하되, **별칭 단독 행이 리스트에 중복 표출되지 않는다**.
4. 저장(Update) 시 **등록구분=대표인 단 하나의 행만** 덮어쓴다. 별칭 텍스트 수정은 본 저장 경로에서 다루지 않는다.

### 1.3 비목표 (현재 범위 밖)
- 별칭 행의 전용 편집 UI / 별칭 텍스트 일괄 수정
- 대표·별칭 행 삭제·병합 마법사
- 실시간재고·POS 매칭 알고리즘 변경 (단, `materialMaster_()`가 별칭을 읽음)
- 프론트에서 `품목명 ➔ 본체명` 동적 합성 표시 (폐기됨)

## 2. 용어 정의

| 용어 | 정의 |
|------|------|
| 원재료코드 | `M` + 구분프리픽스 + 일련번호. 예: `M1010`, `M8003` (5자리 이상) |
| 대표 | 한 코드의 정식 마스터 행. 재고·환산·규격의 기준 |
| 별칭 | 동일 코드를 공유하는 영수증명 매핑 행. 리스트 단독 표시 금지 |
| 미등록 | 코드가 없거나 대기 상태. OCR 후 카탈로그에 올라온 미매핑 품목 |
| 등록제외 | 앞으로 다루지 않을 품목. 입고 IGNORE와 연동 가능 |
| 레거시 `등록` | 구 상태값. 읽기 시 반드시 `대표`로 정규화 |
| aliases | API/화면용 문자열 배열. 별칭 행·G열 토큰을 합친 표시용 목록 |
| Dictionary Row | 대표/별칭을 시트에 각각 독립 Row로 두는 아키텍처 |

## 3. 시트 데이터 계약 (`원재료관리`)

### 3.1 컬럼 맵 (0-based / 1-based)

| Index | 열 | 헤더명 | 설명 | 대표 | 별칭 | 미등록 |
|------:|----|--------|------|:----:|:----:|:------:|
| 0 / A | A | 품목명 | 대표=공식명, 별칭=영수증 표기명, 미등록=대기명 | ● | ● | ● |
| 1 / B | B | 원재료코드 | **대표만** 채움. 별칭·미등록은 빈칸 | ● | ○(비움) | ○ |
| … | … | **대표코드** | **별칭의 FK**. 대표 마스터의 B코드 참조. 대표 행은 빈칸 | ○ | ●(FK) | ○ |
| 2 / C | C | 입고규격(규격) | 예: Box, Kg | ● | △ | △ |

| 6 / G | G | 영수증별칭 | 물리 텍스트. pipe(`\|`) 또는 단일 별칭명 | △ | ● | △ |
| 7 / H | H | 등록일시 등 | 등록 시각 등 | △ | △ | ○ |
| … | … | 등록구분 | `대표`/`별칭`/`미등록`/`등록제외` | ● | ● | ● |
| … | … | 영수증위치 | 명세서 이미지 URL (반정규화) | △ | △ | △ |

- `등록구분`·`영수증위치`·`영수증UPTIME`은 헤더명으로 탐색한다 (고정 열 번호 아님). 없으면 생성한다.
- ● 필수 · △ 선택/복사 · ○ 보통 비움

### 3.2 등록구분 상태값 (정규화 규칙)

| 시트 값 | 정규화 결과 | 비고 |
|---------|-------------|------|
| `대표` | 대표 | 정식 |
| `등록` | **대표** | 레거시 호환 |
| `별칭` | 별칭 | 독립 행 |
| `미등록` | 미등록 | 코드 없을 때 기본 |
| `등록제외` | 등록제외 | |
| `IGNORE` / `영구제외` | 등록제외 | |
| (빈칸) + 코드 있음 | 대표 | |
| (빈칸) + 코드 없음 | 미등록 | |

구현: `normalizeRegStatus_(value, hasCode)`

### 3.3 코드 채번 규칙

| 구분 | 프리픽스 |
|------|----------|
| 고기 | M1 |
| 주류 | M2 |
| 하이볼 | M3 |
| 식사 | M4 |
| 사이드 | M5 |
| 음료 | M6 |
| 야채 | M7 |
| 공산품 | M8 |
| 기타 | M9 |

- 신규 **대표**만 `nextMaterialCode_(category, master)`로 자동 채번한다.
- **별칭**은 기존 대표 코드를 재사용한다 (중복 코드 허용).
- 동일 코드에 `대표` 행은 **논리적으로 1개**여야 한다. (읽기 시 첫 대표만 채택)

### 3.4 행 관계 예시 (대표코드 FK)

```
Row 10: 품목명=스테이크목살, 원재료코드=M1010, 대표코드=(빈칸), 등록구분=대표
Row 41: 품목명=롯데) 몽쉘생크림, 원재료코드=(빈칸), 대표코드=M1010, 등록구분=별칭
Row 55: 품목명=신규OCR품목, 원재료코드=(빈칸), 대표코드=(빈칸), 등록구분=미등록
```

화면 리스트 결과:
- `M1010` 한 줄 (이름=스테이크목살, aliases=`["롯데) 몽쉘생크림", …]`)
- `신규OCR품목` 한 줄 (미등록)
- Row 41은 **단독 리스트 행으로 나오지 않음** (FK로 aliases에만 합침)

레거시 호환: 별칭 행에 `대표코드`가 비고 B에 코드가 있으면 B를 FK로 간주 (`aliasForeignKey_`).

### 3.5 연관 시트 `원재료입고` (저장 부수효과)

| 열(대략) | 용도 |
|----------|------|
| H(7) | 영수증 품목명 |
| M(12) | 원재료코드 (연결 시 기록) |
| N(13) | 공식명 |
| O(14) | 최종반영수량 |
| … | IGNORE / 영구제외 마커 |

- create/link 시 동일 영수증명·미코드 입고 행에 코드를 넣는다.
- update(대표 수정)에서는 입고 자동 수집을 하지 않는 것이 기본이다.

## 4. 아키텍처 원칙

### 4.1 단일 시트 1회 조회 (Read)
- 화면 진입 시 **`원재료관리`만** 읽어 목록을 만든다. (`jobUnregisteredList`)
- 영수증 이미지가 비어 있으면, 동일 세션에서 만든 `원재료입고` 메타 인덱스로 **보강**할 수 있다 (목록용 추가 시트 풀스캔 최소화 목적의 인덱스).
- Gemini/OCR 호출 없음.

### 4.2 1코드 = 1객체 (API 계약)
클라이언트 `groups[]` 규칙:

1. `등록구분=대표` + B(원재료코드) 있음 → 객체 생성 (`aliases: []`, 대표코드 무시)
2. `등록구분=별칭` → `대표코드`(FK, 없으면 레거시 B)로 부모 찾아 `aliases`에 품목명(A) push. **groups 단독 push 금지**
3. `미등록` / `등록제외` → 개별 객체
4. 대표가 없는 고아 별칭 → 리스트에 올리지 않음 (스킵)
5. 동일 코드 대표가 여러 행이면 **첫 대표만** 채택

### 4.3 저장 보호 (Update)
- 원재료코드가 있으면 `findRepresentativeSheetRow_`로 **대표 행만** 찾아 A~F(+등록구분=대표) 갱신
- **G열·별칭 행은 Update 경로에서 수정하지 않음**
- 별칭 등록/수정은 link 등 **별도 프로세스**로 분리

### 4.4 materialMaster_ (타 기능 공용)
- OCR 매칭·입고 환산 등에서 사용
- 코드 기준으로 대표를 본체로, 별칭 행명·G열 토큰을 aliases로 합침
- `등록제외`는 마스터에서 제외

## 5. 백엔드 API 명세

### 5.1 목록 조회 — `jobUnregisteredList` / action `jobUnregisteredList`

**요청:** PIN 인증  
**응답:**

```json
{
  "groups": [
    {
      "key": "c10",
      "sheetRow": 10,
      "name": "스테이크목살",
      "code": "M1010",
      "regStatus": "대표",
      "aliases": ["롯데) 몽쉘생크림"],
      "suggestedCategory": "고기",
      "suggestedSpec": "Kg",
      "suggestedConversion": 1,
      "suggestedStockUnit": "kg",
      "receiptUrl": "https://...",
      "receiptUptime": "2026-11-06 12:00:00",
      "imageUrl": "...",
      "imageVer": "...",
      "units": ["Kg"],
      "count": 0,
      "rows": []
    }
  ],
  "materials": [{ "code": "M1010", "name": "스테이크목살", "category": "고기" }],
  "categories": ["고기", "주류", "..."],
  "version": "2026-11-06-j55"
}
```

**처리 순서**
1. 시트 전 행 순회 → rawRows (+ 영수증 메타 보강)
2. 대표만으로 byCode / list 구성 (+ 대표 G열 pipe 토큰 → aliases)
3. 별칭 행 → `aliasDisplayLabel_(품목명, G)`를 부모 aliases에 push
4. 미등록·등록제외 append
5. 코드 오름차순 정렬, 코드 없는 항목은 맨 뒤

**별칭 표시명 우선순위:** 품목명(A) > G열 `➔/→/=>` 좌측 > G열 전체

### 5.2 일괄 저장 — `jobRegisterUnregisteredBatch`

- `items[]`를 순회하며 `jobRegisterUnregistered` 호출
- 부분 실패 허용 (`saved` / `failed` / 메시지 합본)

### 5.3 단건 저장 — `jobRegisterUnregistered`

| mode | 조건 | 시트 동작 | 입고 동작 |
|------|------|-----------|-----------|
| `update` | 코드 존재 | **대표 행만** A~F 덮어쓰기, 등록구분=`대표`, **대표코드 빈칸**. G·별칭행 미수정 | 기본 자동수집 안 함 |
| `create` | 코드 없음 | 신규 코드 채번(B), 대표코드 빈칸, 등록구분=`대표` | `syncStagingMappedCode_` — 매핑 열에 마스터 코드 |
| `link` | 미등록→기존 | B 비움, **대표코드=마스터코드**, 등록구분=`별칭`. 대표 행 미수정 | 동일 sync — 매핑 열에 마스터 코드 |

**Update 필수 가드**
```
repRow = findRepresentativeSheetRow_(catalog, statusCol, code)
없으면 master[code].sheetRow 폴백
그래도 없으면 에러: "{code} 대표 원재료가 없습니다."
```

### 5.4 등록제외 — `jobIgnoreUnregistered`

- 선택 항목의 catalog `sheetRow` → 등록구분=`등록제외`
- 관련 입고 행 → M=`IGNORE`, N/상태=`영구제외`

## 6. 프론트엔드 화면 명세

### 6.1 진입점
- 메뉴 그룹: **배치작업**
- 메뉴명: **1. 원재료 코드 관리**
- 화면 제목: 원재료 코드 관리
- 상태: `state.unregOpen`, 데이터: `state.unregGroups`

### 6.2 레이아웃
- 좌: 스크롤 리스트 (`#unregScrollArea`) + sticky 헤더
- 우: 선택 행 영수증 뷰어 (wheel zoom/pan)
- 상단: 필터 Select · [등록제외] · [저장] · [닫기]

### 6.3 리스트 컬럼

| 컬럼 | CSS(요지) | 내용 |
|------|-----------|------|
| 체크 | `w-10` | 일괄 선택 |
| 원재료코드 | `w-24 text-center` | `<input readonly disabled>` 수정 불가. 없으면 placeholder `-` |
| 품목명 | `flex-1 min-w-[150px]` | 수정 가능 인풋 |
| (품목명 아래) | — | `aliases` 파란 뱃지 |
| 기존/신규 | `w-20` | 미등록: 신규/기존. 대표: 수정(disabled) |
| 구분 | `w-20` | 카테고리 |
| 규격/환산/단위 | 고정폭 | 신규·대표 수정 시 편집. link 시 코드 검색창 |
| 등록구분 | `w-24` | Select: 대표/미등록/등록제외 + 뱃지 |

**별칭 뱃지 HTML 계약**
```html

  <span class="px-2 py-0.5 text-xs bg-blue-100 text-blue-700 rounded-full">별칭명</span>

```

### 6.4 필터
- 옵션: `전체` | `대표` | `미등록` | `등록제외`
- 레거시 필터값 `등록`/`별칭` → `대표`로 취급
- 클라이언트에서도 동일 코드 중복·별칭 단독행 방어 필터

### 6.5 등록구분 뱃지 색
| 상태 | 색 |
|------|----|
| 대표 | 초록 |
| 미등록 | 회색 |
| 등록제외 | 빨강 |
| (참고) 별칭 | 리스트 행 아님. aliases 뱃지가 파랑 |

### 6.6 저장 버튼 동작 (`submitUnregisteredBatch`)
1. DOM → draft 수집
2. 체크된 행만 payload 구성  
   - 코드 있음 / 대표 → `mode=update`  
   - 미등록 + 신규 → `mode=create`  
   - 미등록 + 기존 → `mode=link`
3. **aliases / receiptAlias 수정값은 Update payload에 넣지 않음**
4. `jobRegisterUnregisteredBatch` 호출 후 목록 재조회

### 6.7 정렬
- 원재료코드 오름차순 (numeric locale)
- 코드 없는 항목은 배열 맨 뒤

## 7. 사용자 시나리오 (업무 플로우)

### 시나리오 A — 대표 정보 수정
1. 필터 `대표` 또는 `전체`
2. 행 선택 → 품목명/규격/환산/단위/구분 수정
3. 체크 후 **저장**
4. 시트: 해당 코드의 **대표 행만** 갱신. 별칭 행·뱃지는 그대로

### 시나리오 B — 미등록을 신규 대표로 등록
1. 필터 `미등록`
2. 기존/신규=`신규`, 구분·규격·환산 입력
3. **저장** → 새 코드 채번, 등록구분=`대표`, 입고 미코드 행에 코드 기입

### 시나리오 C — 미등록을 기존 코드에 연결 (별칭 승격)
1. 기존/신규=`기존`, 대표 코드 검색 선택
2. **저장** (`link`)
3. 해당 미등록 행 → 코드 공유 + 등록구분=`별칭`
4. 다음 목록 로드 시 해당 행은 사라지고, 대표 행 aliases 뱃지에 이름이 붙음

### 시나리오 D — 등록제외
1. 항목 체크 → **등록제외**
2. 카탈로그 등록구분=`등록제외`, 관련 입고 IGNORE

## 8. 불변조건 · 금지사항

### 불변조건 (Invariants)
1. API `groups`에 `regStatus=별칭` 객체가 없어야 한다.
2. 동일 `code`의 대표 객체는 groups에 최대 1개.
3. Update는 항상 대표 행을 대상으로 한다.
4. 레거시 `등록`은 읽기 시 `대표`로만 취급한다.
5. 화면 진입 Read는 원재료관리 단일 시트 원칙을 유지한다.

### 금지
1. 프론트에서 `품목명 ➔ 본체명`을 동적으로 합성해 품목명 칸에 표시
2. Update 시 별칭 행을 sheetRow로 덮어쓰기
3. Update 시 G열(영수증별칭) 일괄 재작성
4. 리스트에 동일 코드 다행 렌더

## 10. 수용 기준 (Acceptance Criteria)

| ID | 기준 | 확인 방법 |
|----|------|-----------|
| AC-01 | 동일 코드 대표+별칭이 시트에 있어도 화면에는 1행만 보인다 | 필터 전체에서 코드 중복 없음 |
| AC-02 | 별칭명은 품목명 아래 파란 뱃지로만 보인다 | UI 육안 |
| AC-03 | 시트 `등록`이 `대표`로 보인다 | 뱃지/필터 |
| AC-04 | 대표 저장 후 별칭 행 내용이 변하지 않는다 | 저장 전후 시트 diff |
| AC-05 | 대표 저장은 대표 행 A~F만 변경된다 | 시트 |
| AC-06 | 미등록 신규 저장 시 코드가 채번되고 상태가 대표가 된다 | 시트+화면 |
| AC-07 | 미등록 기존연결 시 해당 행이 별칭이 되고, 재조회 시 대표 aliases에 합쳐진다 | 저장→새로고침 |
| AC-08 | 코드 없는 미등록은 목록 하단에 정렬된다 | 정렬 확인 |
| AC-09 | 가로 스크롤 없이 헤더·행 컬럼이 정렬된다 | sticky 헤더 |
| AC-10 | 화면/서버 버전이 일치한다 | UI `j55` 등 |
